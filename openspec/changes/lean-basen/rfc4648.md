# RFC 4648 — authoritative encoding rules (pinned)

Pulled from <https://www.rfc-editor.org/rfc/rfc4648.txt> 2026-10-18. This is the
single source of truth for Base16/32/64; Base2/4/8/10 have no RFC and are defined
by this package's own spec.

## Base 16 (§8)

- 16-char subset of US-ASCII; 4 bits per char; **no padding** ("a full code word
  is always available").
- Canonical alphabet (Table 5) is **uppercase** `0-9A-F` (values 0-15 → `0..9 A..F`).
- §8 explicitly: "Base 16 encoding is the standard **case-insensitive** hex
  encoding". So an encoder MAY emit either case, but the RFC's own Table 5 and
  §10 vectors use **uppercase** (`BASE16("fo") = "666F"`).
- Decode MUST accept both cases (`0-9`, `A-F`, `a-f`), identifying `A~a` etc.
  as the same nibble.

⇒ `nibbleToHex` emits **uppercase** (canonical); `hexToNibble` accepts
`0-9 A-F a-f`. The isomorphism is _on the 16 nibbles ↔ 16 uppercase digits_;
lowercase is an accepted _alias_, not a second carrier.

## Base 32 (§6)

- 33-char subset (32 + `=`); 5 bits/char; **most-significant-bit first**.
- Alphabet (Table 3), values 0-31 → `A..Z 2..7`; pad `=`.
- Padding (fewer than 40 bits at end):
  - 8 bits → 2 chars + 6 `=`
  - 16 bits → 4 chars + 4 `=`
  - 24 bits → 5 chars + 3 `=`
  - 32 bits → 7 chars + 1 `=`
  - 40 bits → 8 chars, no pad

## Base 64 (§4)

- 65-char subset (64 + `=`); 6 bits/char; 24-bit (3-octet) groups → 4 chars.
- Alphabet (Table 1), values 0-63 → `A..Z a..z 0..9 + /`; pad `=`.
- Padding:
  - 8 bits → 2 chars + 2 `=`
  - 16 bits → 3 chars + 1 `=`
  - 24 bits → 4 chars, no pad

## Test vectors (§10) — the byte-exact gate for the bench lane

```
BASE16("")            = ""
BASE16("f")           = "66"
BASE16("fo")          = "666F"
BASE16("foo")         = "666F6F"
BASE16("foob")        = "666F6F62"
BASE16("fooba")       = "666F6F6261"
BASE16("foobar")      = "666F6F626172"

BASE32("")            = ""
BASE32("f")           = "MY======"
BASE32("fo")          = "MZXQ===="
BASE32("foo")         = "MZXW6==="
BASE32("foob")        = "MZXW6YQ="
BASE32("fooba")       = "MZXW6YTB"
BASE32("foobar")      = "MZXW6YTBOI======"

BASE64("")            = ""
BASE64("f")           = "Zg=="
BASE64("fo")          = "Zm8="
BASE64("foo")         = "Zm9v"
BASE64("foob")        = "Zm9vYg=="
BASE64("fooba")       = "Zm9vYmE="
BASE64("foobar")      = "Zm9vYmFy"
```

Note these vectors are the _uppercase_ canonical base16 output; `BASE16("fo") =
"666F"` (not `"666f"`). This confirms the bench lane must byte-check **uppercase**
hex, and that a lowercase hex input must still decode.
